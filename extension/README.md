# Context OS browser extension (Phase 2)

Build with `npm.cmd run build:extension` on Windows (`npm run build:extension` elsewhere). In Chrome/Chromium, open `chrome://extensions`, enable Developer mode, choose **Load unpacked**, and select the generated `extension/dist` directory. The extension is local development software; do not publish it yet.

Run the web app and API, sign in, and choose **Connect extension** in the web app sidebar. Copy its ten-minute pairing code. Click the extension icon, paste the code, and connect. The local API and web app addresses are prefilled. For a hosted HTTPS environment, enter its API and web origins; Chrome will request access to that API host. The paired credential can only use extension capture endpoints, is revocable with **Disconnect extension**, and expires after 90 days. A revoked or expired credential prompts pairing again.

Pairing does not save the Context OS setup tab. After pairing, open the page you want to keep; clicking the extension icon saves the active HTTP(S) tab immediately. The popup shows progress and then whether readable text was saved, the URL was saved without text, or an identical capture already exists. Add a note or a project in the confirmation panel. **Save visible screenshot** is optional and captures only the visible tab after you press it. **Open in library** opens the exact saved memory. If extraction is restricted, retry from the popup or click the icon again when the page becomes accessible.

The extension declares `activeTab`, `scripting`, and `storage`, plus local API host access and optional HTTPS API host access. It injects only after a user clicks its icon. The text collector skips forms, inputs, textareas, contenteditable areas, hidden elements, and script/style content. It sends normalized text, URL, title, capture time, and optional user-entered note; it never sends page HTML. The server enforces a 2 MiB text limit and 20 MiB screenshot limit. Chrome's [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting), and [cross-origin request](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests) documentation describe these capabilities.

Before checking the Phase 2 exit, verify the unpacked extension in a real browser on: an ordinary article, a dynamic page after text appears, a page where script injection is blocked, a signed-in page that you own, a repeated save of the same URL, and a non-HTTP tab. Confirm that form values and hidden content are absent from the saved text, that metadata-only captures remain in the Library, and that another account cannot open the capture. This manual browser matrix has not yet been completed.
