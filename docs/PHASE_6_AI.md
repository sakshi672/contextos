# Phase 6 Intelligent Memory implementation notes

Intelligent Memory is optional and off for every new account. The local server currently has no provider key. No saved content is sent to a model unless a server operator configures `CONTEXT_OS_OPENAI_API_KEY` and the account owner enables AI after seeing the cloud-processing disclosure and setting a monthly token limit. Disabling AI leaves keyword search, capture, projects, graph, and timeline available. The settings screen can also delete derived embeddings, suggestions, and answers.

The first adapter uses OpenAI's [Embeddings API](https://developers.openai.com/api/reference/resources/embeddings/methods/create) with `text-embedding-3-small` at 1536 dimensions and the [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create) with `gpt-6.1-terra`, strict structured output, and `store: false`. Provider calls happen only in the backend. The API key belongs in the ignored `backend/.env` for local work or a deployment secret store, never in the frontend or extension. Restart both API and worker after adding it. For production, verify current model availability and [pricing](https://developers.openai.com/api/docs/pricing) before setting limits. The product limit is in tokens, not currency.

The [OpenAI API data controls](https://developers.openai.com/api/docs/guides/your-data) say API inputs and outputs are not used for training by default unless the organization opts in. `store: false` avoids persistent Responses application state; provider abuse-monitoring retention may still apply. The server does not set an opt-in training flag. A public launch needs a complete privacy notice and a provider/retention review.

Migration `0009` installs pgvector and account-scoped AI tables. Migration `0010` invalidates embeddings, suggestions, and cached answers on source changes and removes answers on memory deletion. The worker embeds at most 12,000 characters per memory from title, note, and latest active source text. It retries transient failures with backoff; a budget-exhausted job stops until AI is re-enabled. Search fuses the first 100 keyword and 100 vector candidates, preserves existing kind/source/date/project/tag/collection filters, labels semantic matches, and falls back to keyword results if AI is disabled, unconfigured, over budget, or the provider fails. It does not perform visual-image matching; image text is available only after OCR.

The on-demand assistant reads at most 12 project memories or 12 selected memories, up to three passages per memory, with source text truncated to 1,200 characters per passage and at most 24 total passages. It labels facts, inferences, and missing evidence and verifies that cited IDs belong to supplied, account-owned passages before returning claims. Citation validation checks source identity, not whether a claim is semantically true; users must review the underlying source. Cached results are keyed by task, question, model, and supplied source snapshot. Similarity suggestions require explicit approval or dismissal; approval creates a regular, reversible relationship or project assignment. The similarity percentage and titles are a discovery clue, not proof of a relationship.

The live PostgreSQL tests mock provider responses and cover opt-in, hybrid retrieval, budget fallback, citation ID rejection, cache reuse, isolation, suggestion review, and deletion. They do **not** establish real model quality or accurate production costs. Before Phase 6 exit, run vague-query evaluation on the Phase 0 corpus against the keyword baseline with a real key; inspect grounded answers for citation accuracy, unsupported claims, and useful missing-evidence behavior. Also complete entity/relationship and theme/tag/collection suggestions and make low-confidence alternatives explicit.
