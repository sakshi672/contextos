# Phase 6 Intelligent Memory implementation notes

Intelligent Memory is optional and off for every new account. The local server currently has no provider key. No saved content is sent to a model unless a server operator configures `CONTEXT_OS_OPENAI_API_KEY` and the account owner enables AI after seeing the cloud-processing disclosure and setting a monthly token limit. Disabling AI leaves keyword search, capture, projects, graph, and timeline available. The settings screen can also delete derived embeddings, suggestions, and answers.

The first adapter uses OpenAI's [Embeddings API](https://developers.openai.com/api/reference/resources/embeddings/methods/create) with `text-embedding-3-small` at 1536 dimensions and the [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create) with `gpt-6.1-terra`, strict structured output, and `store: false`. Provider calls happen only in the backend. The API key belongs in the ignored `backend/.env` for local work or a deployment secret store, never in the frontend or extension. Restart both API and worker after adding it. For production, verify current model availability and [pricing](https://developers.openai.com/api/docs/pricing) before setting limits. The product limit is in tokens, not currency.

The [OpenAI API data controls](https://developers.openai.com/api/docs/guides/your-data) say API inputs and outputs are not used for training by default unless the organization opts in. `store: false` avoids persistent Responses application state; provider abuse-monitoring retention may still apply. The server does not set an opt-in training flag. A public launch needs a complete privacy notice and a provider/retention review.

Migration `0009` installs pgvector and account-scoped AI tables. Migration `0010` invalidates embeddings, suggestions, and cached answers on source changes and removes answers on memory deletion. Migrations `0011` and `0012` add reviewed named-entity assignments, source references for proposals, and reviewed-AI relationship provenance. The worker embeds at most 12,000 characters per memory from title, note, and latest active source text. It retries transient failures with backoff; a budget-exhausted job stops until AI is re-enabled. Search fuses the first 100 keyword and 100 vector candidates, preserves existing kind/source/date/project/tag/collection filters, labels semantic matches, and falls back to keyword results if AI is disabled, unconfigured, over budget, or the provider fails. Common remembered phrases for an approximate saved date, source domain, or file type act as visible, soft ranking hints when AI search is available; they do not exclude other results or replace explicit filters. When the strongest semantic match is weak, the response includes up to three separately ranked keyword alternatives. Similarity is a retrieval signal, not a calibrated probability. The product does not perform visual-image matching; image text is available only after OCR.

The on-demand assistant reads at most 12 project memories or 12 selected memories, up to three passages per memory, with source text truncated to 1,200 characters per passage and at most 24 total passages. It labels facts, inferences, and missing evidence and verifies that cited IDs belong to supplied, account-owned passages before returning claims. Citation validation checks source identity, not whether a claim is semantically true; users must review the underlying source. Cached results are keyed by task, question, model, and supplied source snapshot. Similarity suggestions require explicit approval or dismissal; approval creates a regular, reversible relationship or project assignment. The similarity percentage and titles are a discovery clue, not proof of a relationship. Project theme suggestions use a **local recurring-text heuristic** over titles, notes, and a bounded excerpt of active saved text. It suggests single-word tags and repeated two-word collection names. Each approval applies only to the named memory; the user can remove assignments through ordinary organization controls. These terms are text patterns, not verified named entities or model-inferred themes.

The analysis action can propose a specific directed relationship between two memories and up to five named entities copied from their saved text. The server verifies that each proposed quote occurs in the supplied, account-owned source text, that an entity name occurs in its quote, and that the source snapshot remains current before storing a pending proposal. The reviewer can open quoted sources and approve or dismiss each proposal. Approved relationships retain `reviewed_ai` provenance in Connections and can be edited or deleted there. Approved entity assignments retain their quote and provenance and can be removed from the memory panel. A valid quote establishes traceability, not the truth of the relationship or correctness of the entity category. Similarity alone is never presented as a typed relationship.

The live PostgreSQL tests mock provider responses and cover opt-in, hybrid retrieval, weak-match alternatives, budget fallback, citation ID rejection, cache reuse, isolation, suggestion review, quoted-evidence rejection, reversal, and deletion. They do **not** establish real model quality or accurate production costs. Before Phase 6 exit, run vague-query evaluation on the Phase 0 corpus against the keyword baseline with a real key; inspect grounded answers and model proposals for citation accuracy, unsupported claims, useful missing-evidence behavior, and relationship/entity precision.
