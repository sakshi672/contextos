# Phase 1 PostgreSQL foundation

The web app uses this FastAPI/PostgreSQL backend for account registration, login, logout, cookie sessions, CSRF checks, account-scoped note/link memory CRUD, and UTF-8 TXT/Markdown uploads. Originals are saved under the ignored local `data/uploads/` directory; the worker stores extracted text in PostgreSQL with a checksum and processing status. Deletion records filesystem cleanup durably and retries failures in the worker. One-time password recovery is implemented with a local development inbox or configured SMTP; registration email verification, rate limits, and deployment controls are still required before public access. The legacy SQLite API and database are retained only as local backups and regression references.

## Local setup

1. Install and start [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/) with its Linux container backend.
2. Create a virtual environment: `python -m venv .venv`.
3. Install packages: `.venv\Scripts\python -m pip install -r backend\requirements.txt` on Windows.
4. Generate local database settings once: `.venv\Scripts\python -m backend.contextos.local_db init`. This creates ignored `backend/.env` with a random password. Do not run `init` again after the database has data.
5. Start PostgreSQL: `docker compose --env-file backend/.env up -d postgres`. The service binds only to `127.0.0.1:5432` and stores data in the named `contextos_pgdata` volume.
6. Apply migrations: `.venv\Scripts\python -m backend.contextos.local_db migrate`.
7. Start the API: `.venv\Scripts\python -m backend.contextos.local_db serve`.
8. Start the extraction and file-cleanup worker in another terminal: `.venv\Scripts\python -m backend.contextos.local_db worker`.

Run `docker compose --env-file backend/.env ps` to see health status. `docker compose --env-file backend/.env down` stops the database but retains its named volume. The settings file and volume are tied together: changing the password in `backend/.env` does not change an existing PostgreSQL user's password. Hosted deployments instead supply `CONTEXT_OS_DATABASE_URL` through a secret store and run the direct migration/API entry points.

In local development, **Forgot password?** writes a one-time link to an ignored file in `data/recovery-outbox/`; use the newest file addressed to your account. The link expires after 30 minutes, can be used once, and changing the password revokes all sessions. A hosted environment must set `CONTEXT_OS_RECOVERY_DELIVERY=smtp`, `CONTEXT_OS_WEB_ORIGIN` to its HTTPS web origin, `CONTEXT_OS_SMTP_HOST`, `CONTEXT_OS_SMTP_FROM`, and optionally `CONTEXT_OS_SMTP_PORT`, `CONTEXT_OS_SMTP_USERNAME`, and `CONTEXT_OS_SMTP_PASSWORD`. Local recovery delivery is refused when secure cookies are enabled. Recovery requests return the same response for unknown and known addresses, with a five-minute per-account resend window.

`/v1/health/live` checks the process; `/v1/health/ready` checks PostgreSQL connectivity. `POST /v1/auth/register`, `POST /v1/auth/login`, `GET /v1/auth/session`, and `POST /v1/auth/logout` manage a local account session. `POST /v1/auth/recover/request` accepts an email and `POST /v1/auth/recover/reset` accepts a one-time token and new password. Registration and login return a CSRF token and set an HTTP-only session cookie; `GET /v1/auth/session` restores its CSRF token after page reload. Send that token in `X-CSRF-Token` for authenticated writes. `GET/POST /v1/memories` and `GET/PATCH/DELETE /v1/memories/{id}` handle owned records. `POST /v1/uploads/text?filename=...` accepts up to 10 MiB of raw UTF-8 TXT/Markdown bytes and rejects binary or invalid text before storage; `GET /v1/uploads/{memory_id}/original` and `GET /v1/memories/{memory_id}/content` are account-scoped reads. `GET /v1/export` downloads an account-scoped version 1 ZIP, described in [the export format](../docs/EXPORT_FORMAT.md). `POST /v1/import?format=contextos` restores supported records from that ZIP; `format=bookmarks` accepts UTF-8 Netscape browser bookmark HTML. Send raw file bytes and `X-CSRF-Token`; responses report imported, duplicate, and failed items. JSON responses use `{data, error}`; file downloads return files directly. `local_db serve` permits cookies over loopback HTTP; hosted deployments default to secure cookies and must use HTTPS. OpenAPI is available programmatically through `app.openapi()`. Run the worker separately for extraction and failed file cleanup.

Run `.venv\Scripts\python -m unittest discover -s tests -v` to exercise the legacy API, snapshot, and live PostgreSQL account-isolation workflow. The PostgreSQL test skips only when the local database settings or service are unavailable.

The integration tests create a temporary PostgreSQL schema and storage directory, so a separately running development worker cannot claim their jobs. A missing original is recorded as a permanent `missing_original_file` extraction failure; check the original's storage location if this occurs for a real upload.

Phase 2 adds ten-minute pairing codes (`POST /v1/extension/pairings`, signed-in web session), 90-day revocable capture credentials (`POST /v1/extension/tokens`, `GET /v1/extension/session`, `POST /v1/extension/revoke`), and `POST /v1/captures`. The extension sends a Bearer token only to these capture-scoped routes. Captures record the browser URL/title/time, up to 2 MiB of visible readable text, an optional user note and project, and a reason when only metadata could be saved. Repeating the same URL with unchanged text and note returns the existing memory. Optional visible screenshots are uploaded separately to `POST /v1/extension/captures/{id}/screenshot` with a 20 MiB limit. `GET /v1/uploads/{id}/screenshot` is owner-only. See [extension setup](../extension/README.md).

The SQLite prototype contained zero memories at the local PostgreSQL cutover. A read-only snapshot was saved at `data/legacy-snapshot.zip`, and `data/context.db` is retained. The snapshot command is `python -m backend.contextos.legacy_export data/context.db data/legacy-snapshot.zip`; it refuses to overwrite an existing file. This is a migration safeguard, not the final account export or an importer for nonempty SQLite databases.
